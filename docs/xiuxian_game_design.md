# 修仙网页游戏（NAS 部署）设计草案

## 一、项目核心定位

核心定位：轻量型修仙养成类小游戏，以「账号-角色-养成」为核心链路，主打「历练探索+灵宠协同+无商城纯肝养」模式，无任何付费入口，所有道具、资源均通过历练产出，强化随机趣味与养成闭环，兼顾休闲挂机与深度玩法，适配碎片化娱乐场景。

核心亮点：100%历练产出资源；灵宠随机捕捉+协同成长；清晰的境界与战力提升线；实时API日志反馈操作；无冗余付费机制，聚焦玩法本身乐趣。

## 二、整体架构设计（三层递进逻辑）

整体遵循「入口层→过渡层→核心玩法层」递进，确保用户操作流畅，无逻辑断层，各层级功能独立且联动紧密。

### 2.1 入口层：账号主页面（游戏启动首屏）

核心作用：用户身份验证与基础操作入口，保留实时API日志模块，保障操作可追溯。

核心功能

- 注册功能：支持自定义账号+密码注册，无需校验，注册成功后同步生成用户唯一ID。
- 登录功能：仅支持账号密码登录，提供「记住密码」「自动登录」选项，登录失败给予明确提示，连续5次失败限制登录10分钟（防暴力破解）。
- 基础导航：顶部展示游戏名称（如「玄界修仙录」），底部固定「退出游戏」按钮，右侧设置入口（音效开关、画质调节）。

API日志模块（固定悬浮）

- 位置：页面底部固定悬浮，支持展开/收起（默认收起，点击展开显示最近20条日志）。
- 日志内容：实时打印注册、登录、退出等操作的请求参数、响应结果、时间戳，异常操作标注错误码与原因，日志前缀统一为「【修仙日志】」。
- 跳转逻辑：登录成功后自动跳转至角色管理页面。

### 2.2 过渡层：角色管理页面（登录后核心入口）

核心作用：角色创建、选择、删除，展示角色核心信息，作为进入核心玩法的过渡节点。

核心功能

- 角色创建：单账号最多创建3个角色，创建流程为「自定义昵称→选择先天灵根→选择初始形象」。
  - 先天灵根：随机分配金/木/水/火/土五行属性，灵根类型分为单/双/三/四/五灵根。灵根数量越少修炼越快，数量越多修炼越慢。
  - 初始形象：2种基础形象可选（男/女）。
  - 初始道具：创建成功自动获得捕兽绳×5（存入背包）。
- 角色选择：已创建角色以卡片形式展示，卡片包含昵称、等级、境界、灵宠数量、最近登录时间。
- 角色删除：二次确认后删除，日志输出「【修仙日志】角色XXX已删除，数据已清空」。

### 2.3 核心玩法层：游戏内主页面（核心养成场景）

核心作用：承载所有养成玩法（修炼、历练、挑战、灵宠）。

页面布局

- 顶部信息栏：昵称、等级、修为进度、境界、出战灵宠、灵石数量。
- 中部功能区：默认显示修炼模块，底部标签切换修炼/历练/挑战/灵宠。
- 悬浮入口：背包与API日志入口。

## 三、核心玩法详细设计（摘要）

四大核心模块形成闭环：历练获资源 → 修炼/灵宠养成 → 战力提升 → 解锁高阶玩法 → 获取稀有资源。

### 3.1 修炼系统

- 基础修炼：在线/离线计时收益（离线收益不超过8小时）。
- 境界突破：突破概率失败，失败损失30%修为，破障丹可降低失败概率。
- 快速修炼：凝气丹提升修为；淬体丹提升攻击/生命，每日上限5颗。
- 灵宠联动：灵根与灵宠五行匹配层数越高，修炼加成越高。

### 3.2 历练系统

- 场景随境界解锁，时长分10/30/60分钟。
- 历练结束获得修为/灵石/道具；可能触发灵兽与突发事件。
- 灵兽捕捉：捕兽绳消耗，诱兽香加成，匹配度决定成功率。

### 3.3 挑战系统

- 秘境BOSS（每日限定）/同门竞技（AI）/渡劫挑战三类玩法。

### 3.4 灵宠系统

- 背包展示、筛选、出战绑定、放生/解绑。
- 升级、洗髓、进阶、羁绊激活。

## 四、道具体系（摘要）

道具分捕捉类、角色养成类、灵宠养成类、功能增益类、材料类，全部通过历练与挑战产出。


> 目标：在群晖 NAS 上以 Docker 方式部署一个多人可访问的轻量网页修仙游戏；支持注册/登录、创建唯一角色、修炼/历练/挑战/玩家对战/灵宠系统，并具备可扩展的数据与业务层结构。

- **pets**：玩家可持有多个灵宠，但当前出战灵宠可限制为 1 个（增强策略性）。

## 3. 功能模块与玩法

### 3.1 账户/角色

- 注册/登录。
- 每个账号 **只能创建一个角色**。
- 角色可删除（进入冷却期防误删）。

### 3.2 修炼（成长）

- **修炼消耗时间或资源**，获得经验与突破材料。
- 经验积累满后可突破境界（可能失败，失败获得少量返还）。
- 境界影响基础属性与可挑战内容。

### 3.3 历练（随机事件）

- 事件池机制：
  - 收获灵石、装备材料
  - 遭遇妖兽（战斗）
  - 获得灵宠捕捉机会
- 冷却时间限制，防刷。

### 3.4 挑战（PVE）

- 关卡/副本模式：难度与境界挂钩。
- 产出：经验、灵石、材料。
- 可挂机模式（定期结算）。

### 3.5 玩家对战（PVP）

- 排行榜机制，按战力或胜率排序。
- 每日挑战次数限制。
- 失败也能获得少量奖励。

### 3.6 灵宠系统

#### 3.6.1 获取方式
- 捕捉（历练事件触发）。
- 购买（商店）。

#### 3.6.2 培养/升级
- 消耗材料/灵石升级。
- 每级提高基础属性。

#### 3.6.3 进化系统（核心玩法）

- **进化次数限制**：例如每只灵宠最多 6 次进化。
- 每次进化提供 **3 个随机附加属性** 供选择（如暴击率、吸血、闪避、增伤等）。
- 进化成功率随次数递增而下降：
  - 第 1~2 次：90%
  - 第 3~4 次：70%
  - 第 5 次：50%
  - 第 6 次：30%
- 失败惩罚：
  - 进化失败不会掉级，但消耗材料。
  - 可设置“保底机制”：失败 3 次后提升成功率。

#### 3.6.4 平衡性建议
- 属性上限：单项附加属性有上限。
- 属性曲线：进化带来的增幅为递减收益。
- 稀有度影响成长上限但不完全碾压：
  - R/SR/SSR 灵宠基础值不同，但进化空间相近。

## 4. 技术实现建议

### 4.1 Flask 路由层

- `/auth/register`：注册
- `/auth/login`：登录
- `/player/me`：查看角色信息
- `/player/create`：创建角色
- `/player/delete`：删除角色
- `/cultivation/train`：修炼
- `/event/explore`：历练
- `/challenge/pve`：挑战
- `/challenge/pvp`：玩家对战
- `/pet/capture`：捕捉灵宠
- `/pet/upgrade`：灵宠升级
- `/pet/evolve`：灵宠进化

### 4.2 服务层与数据层职责

- **routes**：请求参数校验、鉴权、返回 JSON。
- **services**：业务逻辑与规则处理。
- **storage**：数据读写抽象（JSON 或后续改为 SQLite）。

## 5. 后续扩展

- UI 前端：可使用 Vue/React 接入。
- 数据库迁移：从 JSON 切换到 SQLite / Postgres。
- 任务系统：每日任务、周任务。
- 装备系统：武器/法宝/符箓等。
- 社交系统：宗门/好友/聊天。

## 6. 初期 MVP 建议

1. 账号注册/登录。
2. 角色创建/删除。
3. 修炼（经验成长）。
4. 历练（随机奖励）。
5. 简易灵宠捕捉 + 升级。

> 以上为 MVP，确保可玩性后再逐步增加 PVP 与复杂进化机制。
